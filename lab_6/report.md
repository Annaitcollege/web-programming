# Звіт до лабораторної роботи №6

## Тема: Відображення та фільтрація сенсорів у DOM

## Мета: Навчитися відображати дані сенсорів на існуючій сторінці «Акустична варта» та
фільтрувати їх за районом і статусом. У цій роботі не потрібно додавати або видаляти
сенсори, працювати з формами, localStorage чи іншими Browser API.

## 🚀 Виконання роботи

* **Оновлення HTML-структури сторінки:** У документ `index.html` після блоку «Поточний моніторинг» додано нову секцію `active-sensors`, що містить заголовок, елементи фільтрації (випадаючий список районів `district-filter` та чекбокс `critical-filter`), а також порожній контейнер `.sensor-list` для динамічного виводу карток.
* **Стилізація елементів та статусів (CSS):** Розроблено CSS-стилі для секції активних сенсорів та елементів керування. Для карток сенсорів налаштовано відображення кольорових індикаторів статусів (`normal`, `warning`, `critical`), що дозволяє візуально розрізняти рівні небезпеки шуму.
* **Маніпуляція DOM-деревом (JS):** За допомогою `document.querySelector()` отримано посилання на необхідні елементи сторінки. Реалізовано функцію `createSensorCard()`, яка динамічно створює HTML-структуру картки сенсора із використанням методів `document.createElement()`, `classList.add()` та `textContent`.
* **Рендеринг списку сенсорів:** Створено функцію `renderSensors()`, яка очищує вміст контейнера за допомогою `replaceChildren()` та послідовно додає згенеровані картки сенсорів для масиву даних.
* **Реалізація комбінованої фільтрації:** Написано функцію `applyFilters()`, яка виконує відбір даних методом `filter()`, враховуючи одночасно стан вибору району та прапорця «Тільки критичні».
* **Обробка подій користувача:** На елементи фільтрів додано слухачі подій `addEventListener("change", applyFilters)`, що забезпечує автоматичне та миттєве оновлення списку сенсорів на сторінці при зміні параметрів фільтрації.
* **Фіксація та публікація результатів:** Усі зміни зафіксовано в системі контролю версій Git та оновлено робочу версію проєкту на GitHub Pages.

## ❓ Контрольні питання та відповіді

1. **Для чого використовується `document.querySelector()`?**  
   Для пошуку та отримання першого DOM-елемента на сторінці, який відповідає вказаному CSS-селектору.

2. **Що робить `document.createElement()`?**  
   Створює новий HTML-елемент у пам'яті (наприклад, `article`, `div`, `h3`), який надалі можна наповнити вмістом та додати в DOM-дерево.

3. **Для чого потрібна властивість `textContent`?**  
   Для безпечного встановлення або отримання текстового вмісту HTML-елемента без інтерпретації його як HTML-коду.

4. **Навіщо перед повторним відображенням очищувати `.sensor-list`?**  
   Щоб уникнути дублювання карток при кожному повторному рендерингу (наприклад, при зміні фільтрів).

5. **Що повертає метод `filter()`?**  
   Новий масив, що містить тільки ті елементи вихідного масиву, які успішно пройшли перевірку (умова повернула `true`).

6. **Як отримати вибране значення з `select`?**  
   Звернувшись до властивості `.value` відповідного DOM-елемента (наприклад, `districtFilter.value`).

7. **Як перевірити, чи `checkbox` увімкнений?**  
   Звернувшись до його булевої властивості `.checked` (`criticalFilter.checked`), яка повертає `true` або `false`.

8. **Чому після зміни фільтра потрібно знову викликати `renderSensors()`?**  
   Щоб оновити відображення у DOM-дереві згідно з новим відфільтрованим масивом даних.
