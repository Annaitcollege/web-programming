# Звіт до лабораторної роботи №7

## Тема: Завантаження даних з публічного API та відображення на сторінці

## Мета: Отримати практичні навички роботи з асинхронним JavaScript (`async/await`), виконання HTTP GET-запитів за допомогою `fetch()`, обробки JSON-відповідей від публічного REST API (MockAPI) та динамічного рендерингу отриманих даних у DOM-структуру сторінки.

* **Створення та налаштування MockAPI:** Створено новий проєкт у сервісі MockAPI з префіксом `/api/v1` та ресурсом `sensors`. Заповнено базу даних 6 тестовими об'єктами сенсорів із параметрами `id`, `name`, `district`, `noiseLevel` та `status`.
* **Перевірка API:** Перевірено роботу створеного endpoint за допомогою прямих запитів у браузері та переконанося в отриманні коректного JSON-масиву даних.
* **Оновлення HTML-структури:** У секції `active-sensors` підготовлено контейнер `<div id="sensors-list" class="sensor-list"></div>` для динамічного розміщення згенерованих карток.
* **Реалізація асинхронного завантаження (`fetch`):** У файлі `script.js` створено асинхронну функцію `loadSensors()`, яка виконує HTTP GET-запит до MockAPI endpoint за допомогою `await fetch(API_URL)`, перевіряє успішність відповіді (`response.ok`) та парсить JSON через `await response.json()`.
* **Динамічний рендеринг у DOM:** Реалізовано функцію `renderSensors(sensors)`, яка очищає вміст `#sensors-list` за допомогою `innerHTML = ""` та створює картки для кожного сенсора за допомогою `document.createElement()` та `append()`.
* **Обробка помилок:** Додано блок `try/catch` у функції `loadSensors()` для перехоплення та виведення повідомлення про помилку в разі збоїв мережі чи недоступності API.
* **Перевірка результатів у DevTools:** У вкладці Network інструментів розробника перевірено виконання GET-запиту зі статусом `200 OK` (або `304 Not Modified`) та підтверджено оновлення карток на сторінці при зміні даних у MockAPI..

## ❓ Контрольні питання та відповіді


1. **Що таке API?**  
   API (Application Programming Interface) — це набір правил та протоколів, за допомогою яких одна програма (наприклад, наш frontend) спілкується та обмінюється даними з іншою програмою чи сервером.

2. **Що таке endpoint?**  
   Це конкретна URL-адреса API (наприклад, `https://...mockapi.io/api/v1/sensors`), за якою клієнт звертається для отримання або зміни певного ресурсу.

3. **Для чого використовується HTTP GET?**  
   HTTP-метод GET використовується виключно для читання та отримання даних із сервера без їх зміни.

4. **Що повертає `fetch()`?**  
   Метод `fetch()` повертає `Promise` (обіцянку), який після завершення запиту розкривається в об'єкт `Response`.

5. **Що знаходиться у змінній `response` після `await fetch()`?**  
   У ній знаходиться об'єкт `Response`, який містить метадані про HTTP-відповідь (статус, заголовки, `ok`), але ще не містить готові дані у вигляді масиву чи об'єкта.

6. **Для чого використовується `response.json()`?**  
   Для зчитування тіла відповіді та його асинхронного перетворення (десеріалізації) з тексту формату JSON у повноцінний масив або об'єкт JavaScript.

7. **Чому в типовому GET-запиті використовуються два `await`?**  
   Перший `await` чекає на завершення з'єднання та отримання HTTP-заголовків від сервера (`fetch`), а другий `await` чекає на повне завантаження та розпаршування тіла відповіді (`response.json()`).

8. **Що означає `response.ok`?**  
   Це булеве значення (`true`/`false`), яке вказує, чи був HTTP-статус відповіді успішним (у діапазоні `200–299`).

9. **Де у DevTools можна побачити HTTP-запит?**  
   У вкладці **Network** (Мережа), відфільтрувавши запити за типом **Fetch/XHR**.

10. **Для чого потрібен `try/catch`?**  
    Для перехоплення та безпечної обробки виняткових ситуацій (помилок мережі, сервера чи виконання коду), щоб програма не аварійно зупинялася, а показувала зрозуміле повідомлення користувачеві.
